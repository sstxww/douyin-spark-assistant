# 完全通过 GitHub 浏览器使用

## 第一次打开

1. 登录仓库所属的 GitHub 账号。本仓库默认是 `sstxww/douyin-spark-assistant`。
2. 回到仓库首页，点 **首次创建 GitHub 私有配置环境**；或者 **Code → Codespaces → Create codespace on main**。
3. 创建页选择默认的 2 核环境，检查 GitHub 显示的用量/计费提示，确认创建。首次安装耗时取决于拉取镜像和依赖的网络速度。
4. 等待“火花小助手”浏览器页弹出。没弹出时，在 Codespaces 的下方切换到 **Ports / 端口**，找到 **8765**，点地球图标 **Open in Browser**。看不到端口面板时，使用顶部菜单 **View → Terminal** 打开下面面板，再切到 Ports。
5. 核对端口可见性是 **Private**。Codespaces 私有端口由 GitHub 登录认证控制，不要切为 Public，不要分享预览或验证码。

这是 GitHub 自带云端工作区中的私有网页，而不是普通仓库 Settings 里的新菜单。代码和 daily Actions 留在公开仓库，登录状态不公开。若你已经有一个旧版本 Codespace，可以创建新版工作区；已有私密配置的工作区则应先备份，再更新，不要直接删除。

## 01 连接 GitHub

阅读授权说明并勾选，然后点击 **连接 GitHub**。面板会显示一次性 `XXXX-XXXX` 验证码。点 **打开 GitHub 官方授权页**，复制/输入验证码，使用仓库所有者账号授权 GitHub CLI。回到配置台点 **刷新状态**。

Codespaces 自带登录不等于具备管理 Actions Secrets 的权限，所以需要这个额外授权步骤。默认使用 GitHub CLI 官方 OAuth，不需要创建自定义 OAuth App，不用把 Token 粘进页面或聊天。其 repo、workflow 等权限可能覆盖你的其他仓库；以官方授权页为准，只有理解并信任本项目后才授权。

验证码只给自己使用。授权超时或账号不匹配可以重新连接；私有端口登录过期时在浏览器重新登录 GitHub。没有系统凭据库的 Codespace 可能把 CLI 授权保存在 `.local/web/github-auth/` 的私有文件中。

## 02 添加账号并在云端扫码

输入标签，例如“我的主号”，点 **添加账号**。标签仅方便你识别，不代表抖音已认证这个身份。

点击该卡片的 **扫码登录**。面板启动一个没有其他账号 Cookie 的独立浏览器。预览里显示的是抖音网页，可以直接点击预览里的“登录”和“扫码登录”，然后用自己的手机抖音扫描。

扫码后在预览核对账号、确认能看到私信页面，再勾选 **我已看到私信页面，并核对这是当前卡片对应的本人账号**，点 **保存登录并导入会话**。登录状态在服务端私有目录保存；预览不会上传为 artifact 或截图文件，保存后关闭，15 分钟后也会过期关闭。

同样方法可以添加最多 3 个本人账号。再次扫码使用原卡片的 **重新扫码**，保留原账号配置和去重标识；不要用两个卡片登录同一个账号。

**可能遇到的限制：** 云端 IP、浏览器自动化识别或抖音额外验证可能使二维码不出现或登录不成功；本项目不绕过这些限制。截图预览支持点按，不提供任意远程桌面、输入密码、自动破解验证或本机浏览器接管。需要额外验证且无法完成时先停止，不能承诺所有账号都能完全在云端完成登录。

手机浏览器可以改对象、文案和开关，但首次扫码通常需要另一个屏幕显示二维码，再用登录抖音的手机扫一扫；不承诺单手机完成扫码体验。

## 03 选对象、编辑、复用文案

先在 **正在编辑的账号** 中选择卡片对应的 `a1`、`a2` 或 `a3`。每个账号独立配置。

会话列表只包含扫码时已加载的私信会话，不是完整好友名单。选中后点 **加入选中会话**；缺少的好友可以手动输入完整、唯一备注。好友改名、重名、备注变化都要重新检查。启用账号合计最多 10 位好友。

每行一条候选文案，支持：

```text
今天也来和你打个招呼 🔥
{name}，{weekday}快乐！
{date}，来看看你有没有好好吃饭～
```

固定模式使用第一条；轮换模式按日期选择；每日随机模式同一天保持相同选择。每位好友右侧还能填写专属文案，留空才使用共用文案。

要复用，在模板名里填“日常问候”，点 **保存当前文案为模板**。其他账号选中这个模板，点 **套用到当前账号**。专属文案优先级不变，不会被共用模板静默覆盖。

点击 **保存对象与文案** 后只是保存草稿。草稿不会改变已经发布的云端内容，需要下一步重新发布。删除账号也是从草稿移除：要立即停止先暂停云端。

## 04 发布、检查、开启、重复使用

设置 UTC+8 时间（默认 20:17）。第一次建议仅启用 1 个账号、1 位明确同意接收的好友。

依次点击：

**发布私密配置到 GitHub → 全部账号只检查 → 查看成功结果 → 开启每日自动发送。**

发布会关闭两版的发送开关。如果旧任务正在运行或排队，则暂停后拒绝替换配置；先取消或等它结束，再重试。校验通过后逐个上传账号 Secret，最后写清单；混合版本会拒绝运行。最后保存新的调度时间，不需要编辑 cron。

“只检查”验证登录、对象匹配和聊天输入框，不输入文案、不点发送。“开启”要求当前配置版本、当前 main 代码对应的全账号检查成功，单个账号检查或以前的成功记录不算。

### 立即发送一次

在 **复用配置，手动执行** 中选全部或单个已启用账号，点 **按已保存文案发送一次**，确认后提交任务。要求已经发布且开启发送。当天已尝试过的对象会跳过，不会因为你重复点击而连发。

### 明天继续发送

无需再次操作。Actions 按保存的配置运行，复用登录状态、好友和文案；原登录失效时需要重新扫码、发布和检查。

### 修改内容后继续

回到“对象与文案”，修改并保存；重新发布、全部检查、重新开启。只保存草稿不影响旧的云端配置。

## 暂停与紧急停止

“暂停后续自动发送”把开关置为 false；已开始的任务未必立即停止。“紧急停止并取消任务”还会向 GitHub 请求取消正在运行/排队的两版火花任务。取消是异步请求，需要在 Actions 确认；已经发出的消息不会撤回。

打不开面板时，到仓库 **Settings → Secrets and variables → Actions → Variables → SPARK_WEB_ENABLED → false**。必要时把旧版 `SPARK_ENABLED` 也置 false，并在 Actions 取消任务。

## 下次打开、加密备份

配置完到 GitHub 的 Codespaces 列表停止当前工作区，而不只是关浏览器标签页。停止后 Actions 仍会运行；Codespaces 的保存数据仍占存储，具体按 GitHub 当前计费规则。

以后从同一个 Codespace 恢复，草稿、模板和登录状态会继续使用。**删除前先导出加密备份**：填写至少 12 字符的独立备份密码，点击导出，文件和密码分开放。

换新 Codespace 时，连接 GitHub，然后在“加密备份与恢复”选择备份文件、输入密码、恢复，再重新发布和检查。恢复保留去重密钥和账号标识；GitHub CLI 授权不在备份里，需要重新授权。

如果没有原工作区或备份，Actions Secrets 不能直接读回明文。面板会阻止不同工作区直接覆盖既有密钥，不要删除安装指纹/状态分支来强行重发。原有定时任务可以先在 GitHub 变量页暂停。
