# 验证与边界

## 自动化验证

测试全部使用虚构账号、伪造 Cookie 和模拟 DOM，不对真实抖音账号操作。

- 原网页兼容层：唯一目标、聊天标题、草稿保护、失败标志、发送结果不确定时停止。
- 配置：最多 3 个账号、启用对象合计最多 10 位；账号去重 HMAC 隔离，模板和每日选择可复用。
- 发布：上传前完整校验；活跃任务存在时暂停并拒绝覆盖；只有同版本、同 main 提交、全部账号检查成功后允许开启。
- 数据：API 正常响应不返回 Cookie 或密钥；gzip 解压与 Secret 容量限制；加密备份错误密码和篡改检测；恢复保留账号标识和密钥。
- 网页：CSRF、跨站 Origin/Host 拒绝、私有路径不提供下载、显式发送与授权确认、错误不回显敏感输入。
- 配置台 UI：内存 HTTP 测试桥连接真实 FastAPI 路由与 Chromium DOM，覆盖添加账号、编辑目标与专属文案、保存模板、跨账号套用、草稿发布门禁及移动布局。这个测试不模拟 GitHub 私有端口认证本身。

GitHub Actions 的测试日志给出每次提交的实际结果。模拟测试和环境安装 smoke test 不应被描述为真实账号端到端验收。

## 必须由账号持有人验收

1. Codespaces 首次创建和 GitHub 私有端口认证是否成功。
2. GitHub CLI 官方授权是否被账户或组织政策允许，且能写仓库 Secrets、Variables、workflows。
3. 云端抖音是否能显示有效二维码，并成功扫码进入私信页面。
4. 会话 DOM 是否兼容本账号正在使用的抖音版本，能否精确匹配唯一备注。
5. 一位好友的 check 通过后，由本人确认并试发；在抖音内核对接收对象、文字及是否出现失败状态。
6. 再次运行是否跳过当日记录；次日是否正常执行；登录过期时是否停止。

不承诺抖音网页结构长期不变、不承诺所有账号云端登录成功、不承诺 GitHub 准点调度、不承诺发出一条消息就续火花成功。

## 旧版迁移

网页版使用自己的账号标识与密钥；没有自动迁移旧版单账号登录和去重关系。两版在同一仓库复用 `spark-state` 状态分支和并发组，开关互斥，但**不保证跨版本同一天发送去重**。从旧版切换时先暂停、核对当天消息，最好次日再首次启用网页版。
